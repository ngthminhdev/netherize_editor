🚨 Phát hiện quan trọng (do benchmark lộ ra)

1. [ĐÃ FIX] UI freeze khi gõ vào file lớn. Mỗi phím gõ vào file plain-text lớn chạy regex highlight toàn bộ file đồng bộ trên main thread (submit_parse_for_active_buffer → generate_plaintext_highlight_spans) — chính là cái "beachball" bạn thấy lúc probe đang chạy. Stack sample bắt tận nơi. Fix: chặn theo dung lượng INLINE_PLAINTEXT_BYTE_THRESHOLD = 1 MiB, file lớn hơn bỏ tô màu (không đóng băng UI). 1256 test vẫn xanh.
2. [ĐÃ CHẨN ĐOÁN NGUYÊN NHÂN — cần quyết định kiến trúc] RAM ~3.4 GB khi mở file ~10 MB: đường cong RSS chứng minh balloon xảy ra ngay ở lần render đầu (268MB → 3 629MB trong 2s) rồi plateau; gõ phím KHÔNG làm tăng thêm (phẳng 3 513→3 514MB qua 150 phím). Stack sample bắt được cosmic-text shaping toàn bộ ~150k dòng (ShapeLine/ShapeWord/harfrust) — khớp thiết kế khai báo trong viewport.rs: "Allow cosmic-text to shape full height; scissor clips the visible region". Toàn bộ metadata layout của tài liệu được giữ lại vĩnh viễn để tính vị trí cuộn/jump khi có word-wrap. Sửa triệt để = ảo hoá shaping theo cửa sổ dòng (virtualized shaping) — công việc kiến trúc, không phải bản vá nhỏ.
3. [QUYẾT ĐỊNH SẢN PHẨM] Cap 10 MiB cứng: file large.log 100 MB của bạn bị từ chối mở sau 0.03 ms (exceeds the 10 MiB interactive editor limit). Muốn đạt mục tiêu "mở 50–100MB <1s" phải nâng cap — và phải sửa xong mục 2 trước.
4. Keystroke đầu tiên trên buffer lớn mất ~1.2s đúng 1 lần rồi về 13–16 ms (cold-edit path: debounce flush/git diff init). Nên pre-warm hoặc chia nhỏ.
5. Startup 2.3s / 5.1s giữa 2 lần chạy — số nhiễm session restore + PTY + thời gian cửa sổ được focus. Muốn số "cold start sạch" cần bench riêng (không restore session).
6. Autocomplete/LSP chưa đo tự động được: probe mở src/main.rs nhưng rust-analyzer không attach trong ngữ cảnh probe (không thấy log spawn). Có sẵn rust-analyzer 1.92 trên máy — cần đo thủ công theo dõi tay hoặc instrument thêm hook ready-event.

Phụ lục — điều kiện đo & giới hạn

  • Probe GUI (NETH_PERF_PROBE=1): self-drive qua đường dispatch → AppState → layout → shaping → wgpu submit → present. Latency = dispatch → present (chưa gồm độ trễ OS/compositor, thường <1 frame).
  • e2e runner: CPU-side trước queue.submit — đo phần mutation + layout, không gồm GPU.
  • Criterion: thống kê đầy đủ (warmup, outlier detection), 100 mẫu/scene.
  • GPU timing bật Features::TIMESTAMP_QUERY chỉ khi probe chạy; release giữ Features::empty().
  • Dữ liệu thô: benchmarks/baselines/bench_latest.json · app_probe.json · criterion tại target/criterion/.
  • Hạn chế: CPU% lúc gõ lấy mẫu chưa chuẩn (window quá ngắn → đọc 0.0); scroll interval-p95 còn nhiễu instrumentation — dùng FPS theo time-span (tin cậy).
